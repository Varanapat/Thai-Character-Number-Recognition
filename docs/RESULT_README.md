# ผลการทดลอง — Robust Thai Character Classification

สรุปทุกอย่างที่ทำและผลที่ได้ สำหรับใช้เขียนรายงาน ปรึกษาอาจารย์ และนำเสนอ

- แผนการวิจัยฉบับเต็ม: [README.md](../README.md)
- วิธีรันซ้ำ: [RUNBOOK.md](RUNBOOK.md)
- ตารางดิบ: `results/tables/` | กราฟ: `results/figures/` | ผลรายรอบ: `experiments/`

สถานะ: **การทดลองทั้ง 4 ชุดเสร็จสมบูรณ์แล้ว** ตอบครบทั้ง 4 คำถามวิจัย

---

## สรุปสั้น (อ่านแค่นี้ก็เข้าใจภาพรวม)

1. **ในโดเมนเดียวกัน โมเดลเก่งมาก** — accuracy 99% ทุกสถาปัตยกรรม แม้แต่ CNN ที่เขียนเองขนาด 1.19M พารามิเตอร์
2. **ข้ามโดเมนแล้วพังทันที** — เทรนด้วย D1 ทดสอบกับ D2 เหลือ accuracy **43.5%** จาก 99.1% คือตกไป **55.6 จุด**
3. **Augmentation ช่วยตอนข้าม source ชัดเจน แม้จะไม่ช่วยในโดเมนเดียวกัน** — augmentation ยิ่งแรง accuracy ในบ้านตัวเองยิ่งลดลงเล็กน้อย (99.36% → 98.97%) แต่ accuracy ข้าม source เพิ่มขึ้นต่อเนื่อง (D2: 37.3% → 44.5%, D3: 42.1% → 52.1%) นี่คือการแลกที่คุ้มมาก
4. **โมเดลเล็กที่สุดทำได้ดีที่สุด** — MobileNetV3-Small (1.6M) ได้ macro F1 สูงสุด 0.9813 และเทรนเร็วกว่า DenseNet121 ถึง 5.7 เท่า
5. **เทรนรวมทุก source ช่วยได้จริง** — ได้ accuracy 94.5% บนข้อมูลผสมทั้งสาม เทียบกับ 43–84% ของโมเดลที่เทรนจาก source เดียว
6. **Hard character mining ไม่ช่วยในงานนี้** — คลาสที่แย่ที่สุด (ซ) ดีขึ้น 2.2 จุดจริง แต่ า และ ๅ แย่ลงแทน สุทธิแล้วเท่าทุน เพราะทุกคลาสทำได้เกิน F1 0.92 อยู่แล้ว เพดานจึงเหลือน้อยเกินไป
7. **ข้อสรุปหลัก: Accuracy สูง ≠ Generalize ได้ดี** ซึ่งตรงกับสมมติฐานตั้งต้นของโปรเจกต์

> หมายเหตุ: การทดสอบ unseen font ของ D3 เป็นอันเดียวที่ **ใช้อ้างอิงไม่ได้** เพราะข้อมูลไม่มีรหัสฟอนต์ให้แบ่ง รายละเอียดในหัวข้อ 5.3

## 1. ข้อมูลที่ใช้

รวม 3 source ได้ **163,155 รูป 81 คลาส** (พยัญชนะ สระ วรรณยุกต์ และเลขไทย) รหัสโฟลเดอร์คือรหัส TIS-620 (161 = ก, 240 = ๐)

| | A = D1 (DL - AJ) | B = D2 (THI - C168) | C = D3 (Burapha) |
|---|---|---|---|
| จำนวนรูป | 62,393 | 76,927 | 23,835 |
| จำนวนคลาส | 76 | 68 | 77 |
| รูปต่อคลาส | 1–4,856 (เฉลี่ย 820) | 990–1,195 (เฉลี่ย 1,131) | 168–975 (เฉลี่ย 309) |
| ความไม่สมดุล | สูงมาก | เกือบสมดุล (1.2 : 1) | ปานกลาง (5.8 : 1) |
| ลักษณะภาพ | ขาวดำ เล็กมาก ~15×20 px | ภาพสี ~145×140 px ขอบขาวเยอะ | ขาวดำ จัตุรัส ~24–60 px |

ข้อสังเกตที่มีผลกับทุกการทดลอง
- **D2 ไม่มีเลขไทยเลยทั้ง 10 ตัว** และขาดสระบางตัว จึงมีแค่ 68 คลาส เรื่องนี้ทำให้ค่า macro F1 ของการทดสอบข้าม source ตีความยาก (ดูหัวข้อ 5)
- D1 มีบางคลาสที่มีรูปเพียง 1 รูป ซึ่งกลายเป็นปัญหาใน Experiment C
- ไม่ได้ใช้ `Dataset/Mixed` เพราะไม่มี label

รูปประกอบ: `results/figures/class_distribution.png`, `samples_per_source.png`

## 2. วิธีการ

**การเตรียมภาพ** แปลงเป็นขาวดำ → ตัดกรอบเฉพาะส่วนที่มีหมึก → เติมขอบให้เป็นจัตุรัส → ย่อเป็น 96×96 → ทำซ้ำเป็น 3 channel ให้เข้ากับโมเดล ImageNet

**การแบ่งข้อมูล** แบ่งก่อน augmentation เสมอเพื่อกัน data leakage โดยแบ่งแบบ stratified 80/10/10

**การเทรน** AdamW + OneCycleLR (max_lr 1e-3), label smoothing 0.1, batch 128, pretrained ImageNet, seed 42, รันบน Apple M5 GPU ผ่าน MPS

## 3. Experiment A — เปรียบเทียบสถาปัตยกรรม

เทรนบน D1 ด้วย augmentation แบบ standard เท่ากันทุกตัว 8 epoch

| Model | Accuracy | **Macro F1** | Params | Inference | เวลาเทรน |
|---|---:|---:|---:|---:|---:|
| **mobilenet_v3_small** | 0.9929 | **0.9813** | 1.6M | 3.19 ms | **6.6 นาที** |
| densenet121 | **0.9937** | 0.9794 | 7.04M | 8.48 ms | 37.8 นาที |
| resnet18 | 0.9934 | 0.9792 | 11.22M | 1.35 ms | 24.0 นาที |
| efficientnet_b0 | 0.9929 | 0.9777 | 4.11M | 4.84 ms | 30.7 นาที |
| custom_cnn | 0.9920 | 0.9631 | 1.19M | **0.75 ms** | 17.3 นาที |

**อ่านผลอย่างไร**

- ทุกโมเดลได้ accuracy เกิน 99% แปลว่างานนี้ **ไม่ต้องใช้โมเดลใหญ่** ขนาดข้อมูลและความซับซ้อนของภาพไม่ได้เป็นคอขวด
- accuracy กับ macro F1 ให้คำตอบต่างกัน densenet121 ชนะด้าน accuracy แต่ mobilenet ชนะด้าน macro F1 แปลว่า mobilenet ทำกับคลาสที่มีรูปน้อยได้ดีกว่า ซึ่งเป็นเหตุผลที่ต้องดู macro F1 กับข้อมูลที่ไม่สมดุล
- custom_cnn ตามหลังอยู่ 1.8 จุด (0.9631) แต่เร็วที่สุดในการ inference แสดงว่า pretrained weight ยังมีประโยชน์แม้ภาพตัวอักษรจะต่างจาก ImageNet มาก
- **เลือก mobilenet_v3_small ไปใช้ใน Experiment B–D** เพราะได้ macro F1 สูงสุดและเทรนเร็วกว่า densenet 5.7 เท่า ซึ่งสำคัญเพราะยังต้องเทรนอีกสิบกว่ารอบ

**ข้อควรระวังตอนเขียนรายงาน** ส่วนต่างระหว่างอันดับ 1 ถึง 4 อยู่แค่ 0.4 จุด บน test set 6,239 รูป ซึ่งเล็กกว่าความคลาดเคลื่อนจากการสุ่ม seed จึงไม่ควรสรุปว่า mobilenet "ดีกว่า" densenet อย่างมีนัยสำคัญ ควรพูดว่า **ทุกตัวเสมอกัน แต่ mobilenet คุ้มค่าที่สุดเมื่อคิดต้นทุน** ถ้าอยากให้หนักแน่นต้องรันหลาย seed

รูปประกอบ: `results/figures/model_comparison.png`

## 4. Experiment B — เปรียบเทียบ Data Augmentation

ใช้ mobilenet_v3_small เทรนบน D1 เท่ากันทุกแบบ 10 epoch แล้ววัด 2 สนาม: ทดสอบในโดเมนเดียวกัน (D1)
และทดสอบกับ source ที่ไม่เคยเห็น (D2, D3)

| Augmentation | Acc ใน D1 | Macro F1 | **Acc บน D2** | Gap D2 | **Acc บน D3** | Gap D3 |
|---|---:|---:|---:|---:|---:|---:|
| none | **0.9936** | 0.9790 | 0.3725 | 0.6211 | 0.4210 | 0.5726 |
| standard | 0.9926 | 0.9783 | 0.4015 | 0.5911 | 0.4613 | 0.5314 |
| thai_specific | 0.9909 | **0.9814** | 0.4350 | 0.5558 | 0.4959 | 0.4950 |
| **thai_randaugment** | 0.9897 | 0.9774 | **0.4450** | **0.5448** | **0.5206** | **0.4691** |

`thai_specific` คือ rotation ±10° + perspective + stroke variation + blur + uneven lighting + noise
ซึ่งออกแบบจาก failure mode จริงของภาพเอกสาร ส่วน `thai_randaugment` เพิ่มการสุ่มหยิบ op มาทำซ้ำอีก 2 ชั้น

**ผลนี้คือคำตอบของ RQ2 และเป็นหนึ่งในผลที่ชัดที่สุดของโปรเจกต์**

1. **วัดในโดเมนเดียวกัน augmentation แทบไม่ช่วย** ต่างกันไม่ถึง 0.4 จุด และยิ่งทำแรงยิ่ง accuracy ลดลงนิดหน่อย
   (0.9936 → 0.9897) ถ้าดูแค่ตัวเลขนี้จะสรุปผิดว่า "ไม่ต้องทำ augmentation ก็ได้"
2. **วัดข้าม source augmentation ช่วยชัดเจนและเป็นลำดับ** ยิ่งแรงยิ่งดีขึ้นทุกขั้น
   - บน D2: 37.25% → 40.15% → 43.50% → **44.50%** (ดีขึ้น **7.3 จุด**)
   - บน D3: 42.10% → 46.13% → 49.59% → **52.06%** (ดีขึ้น **10.0 จุด**)
   - generalization gap ลดลงจาก 0.6211 เหลือ 0.5448 (D2) และจาก 0.5726 เหลือ 0.4691 (D3)
3. **สรุปเป็นประโยคเดียว**: ยอมเสีย accuracy ในบ้านตัวเอง 0.4 จุด เพื่อแลกกับความสามารถข้ามโดเมนที่เพิ่มขึ้น
   7–10 จุด เป็นการแลกที่คุ้มมากสำหรับการใช้งานจริง
4. การทดลองนี้ยังตอกย้ำข้อสรุปหลักของโปรเจกต์ว่า **เลือกวิธีจากผลในโดเมนเดียวอาจเลือกผิด** ถ้าวัดแค่ D1
   `none` ดูดีที่สุด แต่จริง ๆ แล้วแย่ที่สุดเมื่อเจอข้อมูลจริงที่ต่างออกไป

**หมายเหตุ** Experiment D ใช้ `thai_specific` เพราะตอนนั้นยังไม่มีข้อมูลนี้ ถ้ารัน Experiment D ใหม่ด้วย
`thai_randaugment` ตัวเลขข้าม source น่าจะดีขึ้นอีกเล็กน้อย

รูปประกอบ: `results/figures/augmentation_examples.png` (เห็นภาพว่าแต่ละแบบทำอะไรกับรูป), `augmentation_comparison.png`

## 5. Experiment D — Generalization (ผลหลักของโปรเจกต์)

### 5.1 Cross-Source Matrix (accuracy)

| Train ↓ / Test → | D1 | D2 | D3 |
|---|---:|---:|---:|
| **D1** | **0.9909** | 0.4350 | 0.4959 |
| **D2** | 0.8330 | **0.8816** | 0.5545 |
| **D3** | 0.8357 | 0.6808 | **0.9895** |

ตัวหนาบนเส้นทแยงคือ in-domain นอกเส้นทแยงคือ cross-source

### 5.2 Generalization Gap

| เส้นทาง | In-domain | Cross-source | **Gap** |
|---|---:|---:|---:|
| D1 → D2 | 0.9909 | 0.4350 | **0.5558** |
| D1 → D3 | 0.9909 | 0.4959 | **0.4950** |
| D2 → D3 | 0.8816 | 0.5545 | 0.3271 |
| D3 → D2 | 0.9895 | 0.6808 | 0.3087 |
| D3 → D1 | 0.9895 | 0.8357 | 0.1538 |
| D2 → D1 | 0.8816 | 0.8330 | **0.0486** |

**สิ่งที่ผลนี้บอก**

1. **โมเดลจำลักษณะของ source มากกว่าจำตัวอักษร** โมเดลที่เทรนด้วย D1 ได้ 99.1% ในบ้านตัวเอง แต่เหลือ 43.5% เมื่อเจอ D2 ทั้งที่เป็นตัวอักษรชุดเดียวกัน
2. **D1 เป็น source ที่ generalize แย่ที่สุด** ทั้งสองทิศออกจาก D1 ตกเกิน 49 จุด น่าจะเพราะรูปเล็กมาก (~15×20 px) ทำให้โมเดลเรียนรู้จากภาพหยาบ พอเจอภาพคมชัดกว่าจึงทำงานไม่ได้
3. **D2 เป็น source ที่ generalize ดีที่สุด** D2 → D1 ตกแค่ 4.9 จุด เพราะ D2 มีรูปเยอะ สมดุล และภาพคมชัด แม้ accuracy ในบ้านตัวเองจะต่ำที่สุด (88.2%) — นี่คือตัวอย่างชัดเจนว่า **accuracy ในโดเมนเดียวไม่ได้ทำนายความสามารถในการ generalize**
4. **D3 อยู่ตรงกลาง** in-domain 99.0% และข้ามไป D1 ได้ 83.6%

**ข้อควรระวังตอนอ้างตัวเลข** D2 ไม่มีคลาสเลขไทย ดังนั้น
- โมเดลที่เทรนด้วย D2 จะไม่มีวันทายเลขไทยถูกเมื่อไปเจอ D1/D3 ทำให้ macro F1 ตกแรงกว่า accuracy มาก (D2 → D1 accuracy 0.833 แต่ macro F1 แค่ 0.5405)
- ถ้าจะเทียบให้ยุติธรรม ควรคิดเฉพาะคลาสที่มีร่วมกันทั้งสองฝั่ง ซึ่งยังไม่ได้ทำ

รูปประกอบ: `results/figures/cross_source_matrix.png`

### 5.3 Unseen Font Test

| | Train | Test | Accuracy |
|---|---:|---:|---:|
| D2 กันกลุ่มผู้เขียนไว้ 25% | 54,342 รูป | 16,547 รูป | 0.9147 |
| ~~D3~~ | — | — | **ใช้ไม่ได้ (ดูด้านล่าง)** |

**D2**: กันกลุ่ม `SetN_F1/M1` ไว้ 25% เป็น test ได้ accuracy 91.5% สูงกว่า random split ของ D2 เอง (88.2%) ด้วยซ้ำ แปลว่าการเปลี่ยนกลุ่มผู้เขียนภายใน D2 **ไม่ได้ทำให้โมเดลแย่ลง** ต่างจากการเปลี่ยน source ซึ่งพังทันที สรุปได้ว่าปัญหาไม่ได้อยู่ที่ "ลายมือคนใหม่" แต่อยู่ที่ "วิธีเก็บและประมวลผลภาพที่ต่างกัน"

**D3 — ผลนี้ใช้ไม่ได้ เป็นบั๊ก ไม่ใช่การค้นพบ** ตารางบันทึกไว้ว่า accuracy = 0.0 สาเหตุคือรหัสที่ดึงมาจากชื่อไฟล์ (A1…E8) ที่คิดว่าเป็นรหัสฟอนต์ แท้จริงแล้วเป็น**รหัสของตัวอักษรเอง** ตรวจสอบแล้วพบว่า 45 จาก 45 รหัสผูกกับคลาสเดียวเป๊ะ ผลคือการกันกลุ่มออกไป = กันทั้งคลาสออกไป โมเดลเทรนด้วย 63 คลาส แต่ถูกทดสอบด้วย 14 คลาสที่ไม่เคยเห็นเลย accuracy จึงเป็น 0 โดยอัตโนมัติ

ชื่อไฟล์ของ D3 ไม่มีรหัสผู้เขียนหรือฟอนต์ที่ใช้แบ่งได้ จึงทำ unseen font test กับ D3 ไม่ได้ ต้องตัดออกจากรายงาน หรือหาข้อมูลผู้เขียนจากแหล่งต้นทางมาเพิ่ม

### 5.4 Combined Training — เทรนรวมทั้ง 3 source

| ทดสอบกับ | Accuracy | Macro F1 |
|---|---:|---:|
| test set ผสมทั้งสาม source (16,316 รูป) | **0.9447** | **0.9405** |
| D1 ทั้งหมด | 0.9929 | 0.9434 |
| D2 ทั้งหมด | 0.9191 | 0.8232 |
| D3 ทั้งหมด | 0.9914 | 0.9781 |

**อ่านผลอย่างไร** เทียบกับตาราง cross-source ที่โมเดล single-source ทำได้แค่ 43–84% เมื่อเจอ source แปลกหน้า การเทรนรวมทำให้ได้ 92–99% กับทุก source พร้อมกัน ตอบคำถาม README ข้อ 13 ได้ว่า **การเห็นข้อมูลหลากหลายตอนเทรนช่วย generalization ได้จริงและช่วยมาก**

**ข้อควรระวัง** ตัวเลขสามแถวล่าง (ทดสอบแยกราย source) คำนวณจากรูป**ทั้งหมด**ของ source นั้น ซึ่งรวมรูปที่อยู่ในชุดเทรนด้วย จึงสูงเกินจริง ตัวเลขที่อ้างอิงได้จริงคือแถวแรก **94.47%** บน test set ที่กันไว้ต่างหาก ถ้าจะใส่รายงานให้ใช้แถวแรกเป็นหลัก

## 6. Experiment C — Hard Character Mining

### 6.1 ตัวอักษรที่ยากที่สุดจริง ๆ

หลังแก้เกณฑ์ให้ไม่นับคลาสที่มีตัวอย่างใน test น้อยกว่า 20 รูป (กันไม่ให้คลาสที่มี 1–2 รูปมาปนแล้วบิดผล)
โมเดล baseline ที่ได้ macro F1 0.9813 บน D1 มีคลาสที่ทำได้แย่ที่สุดดังนี้

| อันดับ | ตัวอักษร | F1 | จำนวนใน test |
|---:|---|---:|---:|

|---|---:|---:|---:|
| baseline | **0.9929** | **0.9813** | **0.9752** |
| หลัง fine-tune | 0.9913 | 0.9785 | 0.9745 |

**คำตอบของ RQ3 คือ ไม่ช่วย ในบริบทนี้** ทั้งสามตัวชี้วัดขยับลงเล็กน้อย (−0.07 ถึง −0.28 จุด)
ซึ่งถือว่าแทบไม่ต่าง แต่ก็ไม่ได้ดีขึ้นตามที่ตั้งสมมติฐานไว้

ดูรายคลาสจะเห็นภาพชัดขึ้นว่าเกิดอะไรขึ้น

| ตัวอักษร | F1 ก่อน | F1 หลัง | เปลี่ยนแปลง |
|---|---:|---:|---:|
| ซ (171) | 0.9286 | 0.9508 | **+0.0222** |
| ช (170) | 0.9804 | 0.9849 | +0.0045 |
| ต ด ค พ | — | — | เท่าเดิม |
| ท (183) | 0.9884 | 0.9854 | −0.0029 |
| ห (203) | 0.9900 | 0.9868 | −0.0033 |
| า (210) | 0.9672 | 0.9551 | **−0.0121** |
| ๅ (229) | 0.9412 | 0.9250 | **−0.0162** |

**อธิบายผลได้ 3 ข้อ**

1. **คลาสที่แย่ที่สุดดีขึ้นจริง** ซ ซึ่งเคยแย่สุด (0.9286) ขยับขึ้น 2.2 จุดเป็น 0.9508 แปลว่ากลไกทำงาน
   ตามที่ออกแบบไว้ คือดึงความสนใจของโมเดลไปที่คลาสที่ทำได้ไม่ดี
2. **แต่ไปทำให้คลาสอื่นแย่ลงแทน** า และ ๅ ตกลง 1.2–1.6 จุด สุทธิแล้วจึงเท่าทุนหรือขาดทุนนิดหน่อย
   เป็นภาพคลาสสิกของการ oversample คือได้อย่างเสียอย่าง
3. **เพดานเหลือน้อยเกินไป** คลาสที่แย่ที่สุดยังได้ F1 0.93 และ macro F1 รวมอยู่ที่ 0.98 อยู่แล้ว
   พื้นที่ให้ปรับปรุงจึงแคบมากจนถูกกลบด้วยความผันผวนปกติของการเทรน

**สิ่งที่น่าสนใจกว่าตัวเลข** คู่ที่โมเดลสับสนที่สุดคือ า ↔ ๅ ซึ่งเป็นตัวอักษรที่หน้าตาเกือบเหมือนกันจริง ๆ
(ๅ ใช้เฉพาะใน ฤๅ และ ฦๅ) กรณีแบบนี้ไม่ใช่ปัญหาที่การสุ่มตัวอย่างจะแก้ได้ เพราะภาพสองคลาสนี้
แทบแยกไม่ออกแม้แต่ด้วยตาคน ควรแก้ที่ระดับข้อมูล เช่น ตรวจ label ด้วย confident learning
หรือรวมสองคลาสเข้าด้วยกันแล้วแยกด้วยบริบทของคำแทน

**บทสรุปที่ใช้ในรายงานได้** hard character mining เหมาะกับโมเดลที่ยังมีคลาสซึ่งทำได้แย่จริง ๆ
(เช่น F1 ต่ำกว่า 0.8) ไม่ใช่โมเดลที่ทุกคลาสเกิน 0.92 แล้ว สนามที่ควรเอาเทคนิคนี้ไปใช้จริงคือฝั่ง
cross-source ที่ accuracy ยังอยู่แค่ 43–52% ไม่ใช่ฝั่ง in-domain ที่เกือบเต็มแล้ว

## 8. ข้อจำกัดที่ต้องพูดในรายงาน

1. **รัน seed เดียว** ผลต่างระดับ 0.2–0.4 จุดใน Experiment A จึงยังสรุปผู้ชนะไม่ได้ในทางสถิติ
   (ผลของ Experiment B ต่างกันถึง 7–10 จุด จึงถือว่าชัดเจนพอ)
2. **macro F1 ของ cross-source ตีความยาก** เพราะจำนวนคลาสของแต่ละ source ไม่เท่ากัน (D2 ไม่มีเลขไทย)
   ควรเทียบเฉพาะคลาสร่วม
3. **ผลของ Experiment C เป็น negative result ที่ต่างกันน้อยมาก** (−0.07 ถึง −0.28 จุด) ซึ่งอยู่ในระดับ
   ความผันผวนของการเทรน ถ้าจะสรุปให้หนักแน่นว่า "ไม่ช่วย" ควรรันซ้ำหลาย seed
4. **unseen font ทำได้แค่ D2** ส่วน D3 ทำไม่ได้เพราะชื่อไฟล์ไม่มีรหัสผู้เขียน/ฟอนต์
5. **Experiment D ใช้ `thai_specific`** ซึ่งตอนนี้รู้แล้วว่า `thai_randaugment` ข้าม source ได้ดีกว่า
   ถ้ารัน D ใหม่ตัวเลขน่าจะดีขึ้นอีก
6. **ตัวเลข combined → รายแหล่ง สูงเกินจริง** เพราะรวมรูปที่ใช้เทรน ให้ใช้ 94.47% เป็นตัวเลขอ้างอิง
7. ยังไม่ได้จัดการ class imbalance เลย (ตั้ง `imbalance: none` ทุกการทดลอง)

## 9. สิ่งที่ควรทำต่อ เรียงตามความคุ้มค่า

1. **รัน Experiment D ใหม่ด้วย `thai_randaugment`** (~1 ชั่วโมง) เพราะรู้แล้วว่าช่วยข้าม source ได้ดีกว่า
   จะได้ตัวเลข cross-source ที่ดีที่สุดเท่าที่วิธีนี้ทำได้ และเป็นการยืนยันผล Experiment B ซ้ำอีกชั้น
2. **รันซ้ำอีก 2 seed** สำหรับ Experiment A และ C เพื่อให้สรุปผลได้อย่างมีนัยสำคัญ
3. ตรวจ label ของคู่ า ↔ ๅ ด้วย `clean_d1.py` (confident learning) เพราะสองคลาสนี้หน้าตาเกือบเหมือนกัน
   จนอาจมีภาพที่ติด label สลับกันอยู่จริง
4. ทดสอบ cross-source เฉพาะคลาสร่วม เพื่อให้ macro F1 เทียบได้ยุติธรรม
5. ลองใช้ hard character mining กับฝั่ง cross-source แทน ซึ่งยังมีพื้นที่ให้ปรับปรุงเยอะกว่ามาก
6. ลองเทรนรวม 2 source แล้วทดสอบ source ที่ 3 (เช่น D1+D2 → D3) เพื่อดูว่าต้องใช้กี่ source
   ถึงจะ generalize ได้ดี
