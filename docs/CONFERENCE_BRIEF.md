# สรุปงาน Thai Character Recognition — เอกสารประกอบการพูดคุย

อัปเดต 25 ก.ย. 2026 | โมเดล: MobileNetV3-Small | ข้อมูลเทรน 3 แหล่ง 163,155 รูป 81 คลาส

---

## 1. สรุป 30 วินาที

เราเทรนตัวจำแนกตัวอักษรไทย 81 คลาส แล้วเปรียบเทียบ **6 กลยุทธ์การเทรน** โดยใช้สถาปัตยกรรมเดียวกันหมด
เพื่อตอบว่ากลยุทธ์ไหนรับมือ **ข้อมูลจากแหล่งที่ไม่เคยเห็น** ได้ดีที่สุด

ผลคือ **เทรนรวมทุกแหล่งไว้ในโมเดลเดียว (S3) ชนะ** ทั้งชนะโมเดลที่เทรนแหล่งเดียว และชนะการรวมผลแบบ ensemble
ตอนทดสอบกับฟอนต์พิมพ์ (PrintAksorn) ซึ่งเป็นคนละโดเมนกับข้อมูลลายมือที่ใช้เทรน ได้ accuracy **83.8%**
เทียบกับโมเดลแหล่งเดียวที่ได้ 59.7–74.1%

---

## 2. ไฟล์ที่รันทำงานยังไง

ไฟล์ที่รันจริงมีแค่ 7 บรรทัด ทำหน้าที่ระบุว่าเป็นกลยุทธ์ไหน แล้วเรียกเครื่องยนต์กลางตัวเดียวกัน

```text
S3_combined.py  (7 บรรทัด)
   │  บอกว่า "ฉันคือ S3 ใช้ D1+D2+D3 เทรนโมเดลเดียว"
   ↓
src/strategy_runner.py   ← เครื่องยนต์กลาง ทุกไฟล์ S1-S6 ใช้ตัวนี้
   ↓
configs/strategy_base.yaml   ← ค่า epoch, lr, batch size, augmentation (ทุกกลยุทธ์ใช้ค่าเดียวกัน)
```

เหตุผลที่ออกแบบแบบนี้: การเปรียบเทียบจะยุติธรรมก็ต่อเมื่อ **ทุกอย่างเหมือนกันหมด ยกเว้นกลยุทธ์**
ถ้าแยกโค้ดเทรนไปคนละไฟล์ จะเผลอตั้งค่าต่างกันโดยไม่รู้ตัว

### โหมดที่ 1 — ไม่ใส่ path = เทรนและวัดผล

```bash
python3 S3_combined.py
```

```text
1. โหลดรายชื่อไฟล์ทั้งหมดใน Dataset/  (163,155 รูป)
2. preprocess ทุกรูป แล้ว cache ไว้ (ครั้งแรก ~5 นาที ครั้งต่อไปโหลดทันที)
      แปลงขาวดำ -> ตัดกรอบเฉพาะส่วนที่มีหมึก -> เติมขอบให้เป็นจัตุรัส -> ย่อ 96x96
3. แบ่งข้อมูลแต่ละแหล่งเป็น train 80 / val 10 / test 10  (seed 42 คงที่ทุกกลยุทธ์)
4. เทรน MobileNetV3-Small 10 epoch
      - augmentation เฉพาะตอนเทรน: หมุน เอียง เบลอ แสงไม่สม่ำเสมอ ความหนาเส้น
      - เก็บ checkpoint ที่ val accuracy ดีที่สุดไว้ที่ models/<ชื่อ>/best.pt
5. วัดผล 2 สนาม
      in_domain = test set ของแหล่งที่ใช้เทรน
      unseen    = แหล่งที่ไม่ได้ใช้เทรนเลย ทั้งแหล่ง
6. เขียนผล 2 ไฟล์
      results/predictions/S3_output.csv    ผลรายรูป: path, คลาสที่ทาย, เฉลย, ถูก/ผิด
      results/tables/strategy_results.csv  สรุป accuracy / macro F1 ต่อท้ายรวมทุกกลยุทธ์
```

### โหมดที่ 2 — ใส่ path = ทำนายรูปใหม่

```bash
python3 S3_combined.py PrintAksorn_dataset/test --labels filename
```

```text
1. โหลด models/mobilenet_d1_d2_d3/best.pt ที่เทรนไว้แล้ว (ไม่เทรนใหม่)
2. preprocess รูปใหม่ด้วยขั้นตอนเดียวกับตอนเทรนเป๊ะ แต่ไม่มี augmentation
3. ทำนาย -> softmax -> เลือกคลาสที่ความน่าจะเป็นสูงสุด
4. --labels filename = อ่านเฉลยจากชื่อไฟล์ (ko_kai_Athiti-Bold.png -> ก)
   แล้วคิด accuracy ให้เลย ถ้าไม่ใส่ก็ได้แค่คำทำนาย
5. เขียน submission/S3_output.csv
```

ความสำคัญของข้อ 2: **preprocessing ต้องเหมือนกันทั้งตอนเทรนและตอนใช้งาน** ถ้าต่างกันแม้นิดเดียว
ความแม่นยำจะตกทันที โค้ดจึงใช้ฟังก์ชันเดียวกัน (`src/datasets/thai_chars.preprocess`) ทั้งสองทาง

### ต่างกันตรงไหนระหว่าง S1-S6

| ไฟล์ | ต่างกันตรง |
|---|---|
| S1, S2, S2b | เทรนโมเดลเดียวด้วยแหล่งเดียว (D1 / D3 / D2) |
| S3 | เทรนโมเดลเดียวด้วยทั้งสามแหล่งรวมกัน |
| S4, S5, S6 | ไม่เทรนใหม่ ใช้โมเดลจาก S1+S2+S2b มารวมผลตอนทำนาย โดยโหวต / เฉลี่ยความน่าจะเป็น / ถ่วงน้ำหนัก |

## 3. ผลการทดลอง

### ทดสอบกับ PrintAksorn (ฟอนต์พิมพ์ 456 รูป — คนละโดเมนกับข้อมูลเทรน)

| กลยุทธ์ | Accuracy | Macro F1 |
|---|---:|---:|
| **S3 รวมทุกแหล่ง (thai_specific)** | **0.8377** | **0.7420** |
| S3 รวมทุกแหล่ง (thai_randaugment) | 0.8224 | 0.6870 |
| S5 เฉลี่ยความน่าจะเป็น | 0.8202 | 0.6871 |
| S4 โหวต | 0.8158 | 0.6872 |
| S2 D3 อย่างเดียว | 0.7412 | 0.5855 |
| S1 D1 อย่างเดียว | 0.6447 | 0.5058 |
| S2b D2 อย่างเดียว | 0.5965 | 0.4457 |

ข้อสรุป 3 ข้อ
1. **รวมข้อมูลตอนเทรน ดีกว่ารวมผลตอนทำนาย** S3 ชนะ ensemble ทุกแบบ และเร็วกว่าด้วย
   เพราะใช้โมเดลเดียว (2.5 ms/ภาพ) แทนที่จะรัน 3 โมเดล
2. **โมเดลแหล่งเดียวรับมือโดเมนใหม่ไม่ได้** ต่างกับ S3 ถึง 14–24 จุด
3. **ensemble ไม่ได้ช่วยเมื่อสมาชิกอ่อน** การเฉลี่ยผลของโมเดลที่เก่งเฉพาะโดเมนตัวเอง
   ไม่ได้สร้างความรู้ใหม่ ต่างจากการให้โมเดลเดียวเห็นข้อมูลหลากหลายตั้งแต่ต้น

### ทดสอบในโดเมนเดิม (test set ที่กันไว้)

| โมเดล | D1 | D2 | D3 |
|---|---:|---:|---:|
| S3 รวมทุกแหล่ง | 0.9912 | 0.8850 | 0.9849 |
| เทรนแหล่งนั้นอย่างเดียว | 0.9909 | 0.8816 | 0.9895 |

S3 ทำได้เท่าโมเดลเฉพาะทางในโดเมนเดิม **โดยไม่เสียความสามารถ** แต่ได้ความทนทานต่อโดเมนใหม่เพิ่มมา

### หลักฐานว่าปัญหาคือ "ความต่างของแหล่ง" ไม่ใช่ "ลายมือคนใหม่"

โมเดลที่เทรนแหล่งเดียวแล้วเอาไปทดสอบอีกแหล่ง (accuracy)

| เทรนด้วย ↓ / ทดสอบ → | D1 | D2 | D3 |
|---|---:|---:|---:|
| D1 | 0.9909 | 0.4350 | 0.4959 |
| D2 | 0.8330 | 0.8816 | 0.5545 |
| D3 | 0.8357 | 0.6808 | 0.9895 |

ตกจาก 99% เหลือ 43% เมื่อข้ามแหล่ง แต่ถ้าเปลี่ยนแค่กลุ่มผู้เขียนภายในแหล่งเดียวกัน accuracy แทบไม่ตก
แปลว่าตัวการคือวิธีเก็บและประมวลผลภาพของแต่ละแหล่ง ไม่ใช่ความต่างของลายมือ

## 4. เรื่องที่ต้องตัดสินใจวันนี้

**โมเดลที่ใช้ตอบชุดจริงกับโมเดลที่ให้ผลดีที่สุด เป็นคนละตัวกัน**

- `submission/FINAL_ANSWER.csv` และ `FINAL_ANSWER2.csv` (สร้างวันนี้ 13:10 และ 13:27)
  ใช้ `models/mobilenet_d1_d2_d3/best.pt` ซึ่งเป็นเวอร์ชัน **thai_randaugment** ได้ 0.8224 / macro F1 0.6870
- เวอร์ชัน **thai_specific** ที่สำรองไว้ใน `models/mobilenet_d1_d2_d3_thai_specific_bak/` ได้ **0.8377 / 0.7420**
  ดีกว่าโดยเฉพาะ macro F1 ที่ห่างกัน 5.5 จุด

ถ้ายังส่งงานทันควรพิจารณารันใหม่ด้วยเวอร์ชัน thai_specific

```bash
python3 S3_combined.py test_dataset --labels filename \
  --checkpoint models/mobilenet_d1_d2_d3_thai_specific_bak/best.pt
```

## 6. ข้อจำกัดที่ควรพูดเอง ก่อนถูกถาม

1. **รัน seed เดียว** ตัวเลขที่ต่างกันต่ำกว่า 1 จุดยังสรุปไม่ได้ แต่ช่องว่าง S3 กับโมเดลแหล่งเดียว
   (14–24 จุด) ใหญ่พอจะสรุปได้
2. **D2 ไม่มีเลขไทยเลย** ทำให้ macro F1 ของโมเดลที่เทรนด้วย D2 ต่ำผิดปกติเมื่อไปเจอชุดที่มีเลข
3. **ยังไม่ได้ทดสอบ S6** (ถ่วงน้ำหนัก) กับชุด PrintAksorn ชุดปัจจุบัน เพราะต้องมีไฟล์น้ำหนักก่อน
4. **คลาสที่ยังแย่** ฆ, ็, ๊, ๅ, บ — ส่วนใหญ่เป็นวรรณยุกต์และสระที่ตัวเล็กมากเมื่อย่อเหลือ 96×96
5. ชุดทดสอบ PrintAksorn เปลี่ยนจำนวนระหว่างทาง (1,000 → 456 รูป) ตัวเลขในเอกสารนี้
   มาจากชุด 456 รูปปัจจุบันทั้งหมด วัดใหม่พร้อมกันวันนี้
