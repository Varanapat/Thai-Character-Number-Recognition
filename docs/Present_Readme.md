## สไลด์ 7 — โครงสร้าง CNN ที่ใช้ (ภาพรวม)

## สไลด์ 8 — การทำงานของ CNN: จุดเด่นของ MobileNetV3-Small

**เนื้อหา** (ความรู้ทั่วไปของสถาปัตยกรรม อธิบายเสริมจากสไลด์ 7)
- **Depthwise Separable Convolution**: แยกการทำ convolution เป็น 2 ขั้น (depthwise + pointwise) แทนที่จะทำ conv ปกติทั้งก้อน ลดจำนวนพารามิเตอร์/การคำนวณได้มาก โดยแม่นยำไม่ต่างกันมาก
- **Squeeze-and-Excite (SE) block**: ให้โมเดล "ถ่วงน้ำหนัก" ความสำคัญของแต่ละ channel เอง แทนที่จะให้ทุก channel สำคัญเท่ากัน
- **h-swish activation**: activation function ที่คำนวณเร็วกว่า swish ปกติ แต่ยังคงประสิทธิภาพใกล้เคียง
- ได้จากการทำ Neural Architecture Search (NAS) มาเพื่อบาลานซ์ accuracy กับ latency บนอุปกรณ์พกพาโดยเฉพาะ — ตรงกับที่ต้องการโมเดลขนาดเล็ก เทรน/ทำนายเร็ว

## สไลด์ 9 — เทคนิค Transfer Learning

**เนื้อหา**
- ทุกสถาปัตยกรรมที่เทียบในสไลด์ 7 ใช้ **pretrained weights จาก ImageNet** (`pretrained: true` ในทุก config) ไม่ได้เทรนจากศูนย์
- เหตุผล: แม้ภาพตัวอักษรไทยจะต่างจากภาพ ImageNet มาก แต่ low-level feature (เส้น, ขอบ, มุม) ที่โมเดลเรียนรู้มาก่อนยังมีประโยชน์ ช่วยให้เทรนเร็วขึ้น/ใช้ข้อมูลน้อยลงได้ผลดีขึ้น
- หลักฐาน: แม้แต่ Custom CNN ที่ไม่ได้ใช้ pretrained (เทรนจากศูนย์) ก็ยังตามหลัง MobileNetV3-Small ที่ใช้ pretrained อยู่ 1.8 จุด (macro F1) ทั้งที่ขนาดพารามิเตอร์ใกล้เคียงกัน — แสดงว่า pretrained weight ช่วยจริง

## สไลด์ 10 — เทคนิค Data Augmentation

**เนื้อหา** (RESULT_README.md ข้อ 4, Experiment B — **นี่คือผลที่ชัดที่สุดของโปรเจกต์**)

## สไลด์ 11 — เทคนิค/แนวคิดที่น่าสนใจ (คะแนนพิเศษ 2%)

**เนื้อหา** — มี 3 ตัวเลือก เลือก 1–2 ตามเวลาที่มี **แนะนำให้เน้น Confident Learning เป็นหลัก** เพราะมีผลจริงเป็นตัวเลขชัดเจน และตอบโจทย์ "แนวคิดที่น่าสนใจ" ได้ตรงที่สุด (ไม่ใช่แค่ลองเทคนิคตามสูตร แต่แก้ปัญหาที่ลึกกว่านั้น)

### ตัวเลือก A (แนะนำ): Confident Learning แยก "label ผิดจริง" ออกจาก "ภาพที่ยากโดยธรรมชาติ"

**ปัญหาที่แก้**: เวลาโมเดลทายรูปหนึ่งผิด มี 2 สาเหตุที่ปนกันอยู่ตลอด — (1) ภาพนั้น**ติด label ผิดมาตั้งแต่ต้น** (noisy label) กับ (2) label ถูกอยู่แล้ว แต่**ตัวภาพยากจริง ๆ** (hard example) ทั้งสองแบบต้องจัดการต่างกันคนละทาง: อันแรกควรแก้ label หรือตัดทิ้ง อันหลังห้ามตัดออกเด็ดขาดเพราะเป็นของจริงที่โมเดลต้องเจอตอนใช้งาน ถ้าให้โมเดลตัวเดียว "ฟันธง" เอง จะแยกสองอย่างนี้ไม่ออก เพราะโมเดลเคยเห็นรูปนั้นตอนเทรนแล้ว การทายของมันจึงลำเอียงเข้าข้าง label เดิม

**วิธีแก้ (Confident Learning แนวเดียวกับ cleanlab)** — ใช้กับ D1 ผ่าน `clean_d1.py`:
```
D1 (ทุกคลาส) + D2 + D3 (ใช้เทรนอย่างเดียว ไม่แตะ)
        ↓
K-fold cross-validation (k=4) — เทรน ResNet50 แต่ละ fold
        ↓  ทำนายเฉพาะ D1 ส่วนที่ "ไม่ได้ใช้เทรน fold นั้น"
Out-of-fold prediction  ← จุดสำคัญ: โมเดลไม่เคยเห็นรูปที่กำลังทายนี้มาก่อนเลย
        ↓
เทียบ label เดิม vs. สิ่งที่โมเดลมั่นใจว่าควรเป็น (confident joint matrix)
        ↓
   ┌──────────────┬────────────────────┬──────────────────┐
   │ moved         │ flagged_review      │ ไม่แตะ (untouched) │
   │ มั่นใจว่าผิด    │ มั่นใจว่าผิด แต่ไม่     │ ไม่ใช่ label issue   │
   │ + รู้ว่าควรเป็น  │ ชัดว่าควรเป็นอะไร      │ = hard example     │
   │ อะไร → relabel │ → ส่งให้คนตรวจ       │ → เก็บไว้เทรนต่อ    │
   └──────────────┴────────────────────┴──────────────────┘
```

**ผลจริงจากการรัน** (`outputs/cleaning/d1_cleaning_summary_20260924_083901.json`, k=4, 4 epoch/fold, img_size 96, move_threshold 0.9):

| | จำนวน | สัดส่วน |
|---|---:|---:|
| D1 ทั้งหมด | 62,519 รูป | 100% |
| ตรวจได้ (คลาสที่มีตัวอย่างพอ) | 62,217 รูป | 99.5% |
| **moved** (มั่นใจว่า label ผิด + รู้คำตอบที่ถูก → relabel อัตโนมัติ) | **78 รูป** | 0.13% |
| **flagged_review** (สงสัยว่าผิด แต่ไม่มั่นใจคำตอบ → รอคนตรวจ) | **126 รูป** | 0.20% |
| ไม่แตะ (hard example ของจริง เก็บไว้เทรน) | 62,013 รูป | 99.7% |

**ประเด็นที่ควรพูดในสไลด์**
- Label noise จริงในภาพ D1 มีน้อยมาก (~0.1%) แปลว่าปัญหาหลักของ D1 **ไม่ได้มาจาก label คุณภาพต่ำ** — เชื่อมกลับไปสไลด์ 15 ได้ว่าทำไม D1 ถึง generalize แย่ที่สุด (สไลด์นั้นสรุปว่าเป็นเพราะ**ลักษณะภาพ** เล็ก/ขาวดำ ไม่ใช่ label ผิด ข้อมูลจาก confident learning นี้ช่วย "ตัดตัวแปร" label noise ออกไปได้ ยืนยันว่าสาเหตุอยู่ที่คุณภาพ/ลักษณะภาพจริง ๆ)
- ออกแบบให้ปลอดภัย: ค่าเริ่มต้นเป็น dry-run เสมอ (แค่เขียน CSV ไม่ย้ายไฟล์จริง) ต้องสั่ง `--apply` เองถึงย้ายจริง และย้อนกลับได้ทุก action ด้วย `--undo` — ไม่แตะ D2/D3 เลย (ใช้แค่เป็นข้อมูลเทรนอ้างอิง) และไม่มีการลบไฟล์ มีแต่ย้าย
- นี่คือตัวอย่างที่ตรงกับสิ่งที่อาจารย์อยากเห็นในข้อ "เทคนิคหรือแนวคิดที่น่าสนใจ" เพราะไม่ใช่แค่ทำตาม assignment (Transfer Learning/Augmentation ที่ทุกกลุ่มต้องมี) แต่เป็นการตั้งคำถามเพิ่มเองว่า "ข้อมูลที่ใช้เทรนสะอาดจริงไหม" แล้วไปหาเครื่องมือ/วิธีมาตอบคำถามนั้นเอง

### ตัวเลือก B: "รวมความรู้ตอนเทรน vs รวมความรู้ตอน inference"** (Model_strategy.md ข้อ 11, RESULT_README.md ข้อ 5.4 + 7)
- เทรนโมเดลเดียวด้วยข้อมูลรวมทั้ง 3 source (**S3 — Combined Training**) เทียบกับเทรนโมเดลแยกราย source แล้วเอามาโหวต/เฉลี่ยความน่าจะเป็นตอนทำนาย (**S4 Majority Vote / S5 Probability Average / S6 Weighted Ensemble**)
- ผล: โมเดลเดียวที่เทรนรวม (S3) ให้ macro F1 บนข้อมูลไม่เคยเห็นสูงกว่า ensemble ทุกแบบ (S3 0.8685 > S5 0.8186 > S4 0.7968) — สรุปว่า **ให้โมเดลเห็นความหลากหลายตั้งแต่ตอนเทรน ดีกว่าพยายามรวมความเห็นทีหลัง** สำหรับงานนี้
- เป็น trade-off ที่น่าคุยต่อได้ในสไลด์: ensemble ต้องรันโมเดลหลายตัว (ช้ากว่า, ใช้ resource มากกว่า) แต่ได้ผลแย่กว่าโมเดลเดียว

### ตัวเลือก C (ถ้าอยากได้เพิ่ม): Hard Character Mining — negative result ที่วิเคราะห์ลึก (RESULT_README.md ข้อ 6.3)
- ลอง oversample คลาสที่แย่ที่สุด 10 คลาส แล้ว fine-tune ต่อ → คลาสที่แย่สุด (ซ) ดีขึ้นจริง (+2.2 จุด) แต่ไปทำให้คลาสอื่น (า, ๅ) แย่ลงแทน สุทธิแล้วแทบไม่ต่าง
- ข้อสรุปที่น่าสนใจ: เทคนิคนี้จะได้ผลดีกับโมเดลที่ยังมีคลาส F1 ต่ำกว่า 0.8 จริง ๆ ไม่ใช่โมเดลที่ทุกคลาสเกิน 0.92 อยู่แล้วแบบนี้ — แสดงว่าเข้าใจข้อจำกัดของเทคนิค ไม่ใช่แค่ลองแล้วจบ

## สไลด์ 13 — ขั้นตอนการฝึกสอนแบบจำลอง

**ควรใส่ pipeline ตอนเทรนด้วย** — ตอบเกณฑ์ "อธิบายขั้นตอนการฝึกสอนแบบจำลอง" ได้ชัดกว่าแค่ลิสต์ hyperparameter เฉย ๆ

```
Dataset/character/, Dataset/number/  (3 source: D1+D2+D3)
        ↓  preprocess (สไลด์ 6) + cache เป็น .npz
        ↓  แบ่ง Train 80% / Validation 20% แบบ stratified ต่อ source
        ↓  รวม train/val ของทั้ง 3 source เข้าด้วยกัน (S3 = combined training)
        ↓  Data Augmentation (thai_randaugment) — ใช้เฉพาะฝั่ง train เท่านั้น
        ↓  MobileNetV3-Small (โหลด pretrained ImageNet weights)
        ↓  Training loop: AdamW + OneCycleLR, label smoothing 0.1, batch 128
        ↓     วนสูงสุด 10 epoch, เช็ค val accuracy ทุก epoch, early stop patience 3
        ↓  เก็บ checkpoint ที่ val accuracy ดีที่สุด -> best.pt
        ↓  ประเมินกับข้อมูลของแต่ละ source (ที่เคยเห็น = in-domain, ที่ไม่เคยเห็น = unseen)
```

**เนื้อหา**
- Optimizer: AdamW, OneCycleLR (max_lr 1e-3)
- Label smoothing 0.1, batch size 128
- Pretrained ImageNet weights, seed คงที่ (42) เพื่อ reproducibility
- **แบ่งข้อมูล Train 80% / Validation 20%** (stratified ตามคลาส แบ่งก่อนทำ augmentation เสมอ กัน data leakage) — ตรงตามเกณฑ์ข้อนี้ของวิชาพอดี
- เทรนบน MobileNetV3-Small ที่ล็อกสถาปัตยกรรมไว้ตัวเดียว เปลี่ยนแค่ตัวแปร "วิธีเทรน/วิธีรวมผล"
- Early stopping (patience 3) เพื่อไม่ overfit

## สไลด์ 15 — สรุปผล Cross-Source Generalization (RQ4 — ไฮไลต์ของโปรเจกต์)

**เนื้อหา** (RESULT_README.md ข้อ 5.1–5.2)

| Train ↓ / Test → | D1 | D2 | D3 |
|---|---:|---:|---:|
| D1 | 99.1% | 43.5% | 49.6% |
| D2 | 83.3% | 88.2% | 55.5% |
| D3 | 83.6% | 68.1% | 98.9% |

- เทรน D1 อย่างเดียว ได้ 99.1% ในบ้านตัวเอง แต่ตก **43.5%** พอเจอ D2 ทั้งที่เป็นตัวอักษรชุดเดียวกัน → เป็นหลักฐานตรงกับสมมติฐานตั้งต้น: **Accuracy สูง ≠ Generalize ได้ดี**
- เทรนรวมทั้ง 3 source ได้ 94.5% บนชุดทดสอบผสม เทียบกับ 43–84% ของโมเดล single-source
- ปิดท้ายด้วยคำตอบ RQ1–RQ4 (ตารางเดียวจาก RESULT_README.md ข้อ 7) เป็นสไลด์สรุป
